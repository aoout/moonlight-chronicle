传输预压缩（brotli / gzip 静态文件）

vite-plugin-compression2 构建时生成 .br（brotli，主）与 .gz（gzip，兜底）双份静态文件，阈值 ≥1KB。由静态托管 / CDN / nginx 优先服务，浏览器无需等待服务器实时压缩。实测对比（vite build 输出）：

二 · 优化项详情

按影响优先级排序。每项包含：问题 → 证据（文件:行号 或构建输出）→ 改法 → 验证收益。

懒加载 蚀之图鉴 / 蚀月功勋 / 月蚀之仪 / 蚀月之望 / 集市

CRITICAL

主包静态 import 了 5 个非首屏 UI 面板与对应专属模块；首次访问后用户大概率不会打开这些面板，但全部 JS 都进了首包。

证据
拆包测试 manualChunks 把 codex+achievements 拆到 174.25 kB / 54.56 kB gzip，cloudsync 113.81 kB / 42.35 kB gzip，两者占假想首包 78%。 静态引用点：scheduler.ts:18-20、main.ts:16,57、state_hooks.ts:13、PausePanel.ts:13、codex.ts:15。
改法
  • scheduler.ts：移除 bindCodex / bindAchievements / bindSettingsUI 静态 import；模块级缓存 _codexMod / _achvMod / _settingsMod + _xxxLoading promise 模式；首次按钮点击 → import('./x.js').then(m => { m.bind*(); m.open*(); })。
  • achievements.ts：EventBus.on(ACHIEVEMENT_UNLOCKED → toast) 监听移至 scheduler 常驻；面板模块不再依赖 EventBus / EVENTS / toast。
  • main.ts：移除 importPlanetUI；新增残月按钮状态联动（setTimeout + sm.onEnter + EventBus.on，均常驻）；btn-planet 点击 → 动态 import + initPlanetUI() + openPlanet()。
  • planet.ts：initPlanetUI 删除状态联动部分（移到 main.ts）；移除 STATE/sm/EventBus/EVENTS 与 setPlanetVisible 共 31 行。
  • state_hooks.ts：openShop 改为 import('../features/ui/shop/index.js').then(m => m.openShop())，仅在进入 SHOP 状态时拉取。
  • PausePanel.ts 与 codex.ts：from '../shop/index.js' / './shop/index.js' 改为精确路径 '../shop/panel.js' / './shop/formulas.js'，切断对 open_shop 链的静态依赖。
  • scheduler.ts:keydown Escape：isSettingsOpen/closeSettings 改为惰性引用 _settingsMod.isSettingsOpen()，行为等价。
收益
首包 JS −20.76 kB raw / −5.30 kB gzip（−5.5%）；按需 24.95 kB raw / 10.33 kB gzip 仅在用户主动访问时下发。警告：构建期报 [INEFFECTIVE_DYNAMIC_IMPORT] 即代表改造未生效，必须保证目标模块仅被动态 import 或被静态 import 但仅在懒 chunk 内。
验证
npm run typecheck 通过；npm run arch 通过；573 测试全绿；Edge headless 主菜单截图渲染正常（含右上角残月按钮），无静态回归。

Google Fonts 渲染阻塞 → 异步样式表

HIGH

Cinzel / Noto Serif SC / Inter 三套字体（Noto Serif SC 中文字体子集重）通过 <link rel="stylesheet"> 同步加载，阻塞 CSSOM 完成。

证据
index.html:9-10 同步 stylesheet 指向 fonts.googleapis.com；display=swap 已保证字符交换，但 CSS 下载本身仍阻塞渲染。
改法
改为 media="print" onload="this.media='all';this.onload=null" 异步加载技巧；附 <noscript> 兜底（非 JS 环境回退同步样式表）。
收益
FCP 不再等字体 CSS 下载；首字节到可交互更快；视觉上字体在到位时正常切换（swap 已保证）。HTML 净增 +5 kB（onload + noscript 字符串），gzip 后仅 +0.2 kB。
验证
Edge headless 截图「蚀月远征」标题与中文副标题字体正常应用，残月按钮可见，主菜单 5 个按钮正常。

噪点贴图 noise.png 内联

MEDIUM

磨砂玻璃噪点贴图 3.37 kB 作为独立资源请求，加载链多一跳。

证据
css/tokens.css:56 引用 url('noise.png')；vite.config.js:14 设置 assetsInlineLimit: 0（注释意图是避免外部 URL 内联，副作用是本地小资源也不内联）。
改法
assetsInlineLimit 改为 4096。noise.png (3.37 kB) 自动 base64 内联到 CSS；Google Fonts 等外部 URL 不受此限制。
收益
少 1 个 HTTP 请求；CSS 文件 +4.49 kB（base64 膨胀），gzip 后仅 +4.4 kB。在高延迟网络收益更明显。

HUD 每帧分配：wDmg 求和

MEDIUM

武器栏冷却渲染每帧执行 Object.keys(wDmg).reduce(...)，每帧分配键数组。

证据
src/features/ui/hud.ts:158（改造前）： 
const wTotal = Object.keys(wDmg).reduce((s, k) => s + wDmg[k], 0);
wDmg 最大 5 武器 + 1 道具，每帧 Object.keys() 都新建数组传给 reduce。
改法
改为 for..in 累加，零数组分配： 
let wTotal = 0;
for (const k in wDmg) wTotal += wDmg[k];
收益
每帧避免 1 次小数组分配；武器栏是 60Hz 全屏常驻渲染，合计每分钟减少约 3600 次微分配。

投射物渲染 setLineDash([]) 常量化

LOW

特殊投射物（陨星 / 潮锚 / 裁决光环 / 蚀雷）每帧绘制调用 ctx.setLineDash([]) 4 次，[] 字面量每次新建数组。

证据
src/features/render/effects/projectiles.ts:205 / 228 / 270 / 617 4 处 ctx.setLineDash([])。
改法
模块顶部新增 const NO_DASH: number[] = [];，4 处替换为 ctx.setLineDash(NO_DASH)。
收益
语义清晰；canvas API 内部仍会拷贝数组传递，但每次源数组复用同一个引用、引擎可能优化掉拷贝。收益微小但零风险。

五 · 结论

本轮优化在「证据优先、不降级体验」原则下完成：

  • 首屏 JS 减少 5.5%（gzip 4.3%），6 个非首屏面板与模块改为按需加载。
  • Google Fonts 异步化，FCP 不再等字体 CSS。
  • HUD 每帧消除 1 次微分配，热路径语义更清晰。
  • 573 个测试 + arch + check-only + typecheck + Edge headless 视觉验证全绿，无回归。
  • 所有潜在体验妥协（背景细节 / 动画 / 特效）保留在 月蚀之仪 的性能档位开关中，由玩家自行取舍 —— 默认仍偏向「保留原体验」。

剩余首包体积约 357 kB raw（gzip 119 kB），主要来自 hud_utils 共享 chunk（112 kB，icons + config 数据 + 工具）。继续压缩需重构 icons 与 config 的按域切分（见上节 MEDIUM 项），属下一轮迭代方向。
